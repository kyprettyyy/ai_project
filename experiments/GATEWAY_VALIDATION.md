# 验证集网关实验

`run_gateway_validation.py` 默认只做免费前置检查，只有明确加 `--run` 才发起付费调用。

比较6种策略：均衡、质量优先、成本优先，以及三个候选模型分别固定调用。
完整验证集80题，每种策略调用一次，共480次回答。编程与摘要用其他两个候选模型交叉评分，最多另有480次评分调用。数学按数值容差、分类按标签完全一致评分。编程评分是AI评价，不是执行代码的通过率。不同被测模型使用不同交叉评委，存在评委偏差，须记录并人工抽查。

输出 manifest.json（不含密钥）、results.jsonl（逐条保存）、summary.json（含评分和费用覆盖率）。再次使用相同输出目录会保留已有结果，只跑未记录的题目；失败记录保留，避免无意再次付费。

前置条件：关闭自动更新；恰好启用 MiMo/HY3/GLM 三个候选模型；人民币单价完整；四类任务的训练专用画像齐全且每组至少30样本。混合历史聚合的 auto-* 画像不允许作为训练专用画像；经过训练任务来源核验的画像需使用 train-only- 开头的发布标识。脚本不会创建或修改画像。

运行前应核实正在运行的网关已包含实验绕过缓存修复。请求使用统一温度0、输出上限4096和随机交错顺序。调用顺序与数据哈希写入清单；每题前后检查模型、供应商、价格和画像快照，变化即停止。在线健康统计仍会随调用更新，因此这不是完全静态的路由模拟；应保存 gateway 决策说明供审计。

```sh
services/evaluation/.venv/bin/python experiments/run_gateway_validation.py \
  --dataset /绝对路径/验证集_validation \
  --output /绝对路径/验证集路由实验
```

免费检查通过后，正式运行在同一命令后增加 `--run`。可加 `--limit 6` 做6个回答的小样本联通检查，必须使用独立输出目录，不能将其当作正式结论。

当前是验证集脚本，拒绝测试集输入。先完成训练评分和训练画像来源核验，再运行验证实验；选定配置后另建冻结的测试集运行清单，不应放开此脚本的split检查混用两种数据。
