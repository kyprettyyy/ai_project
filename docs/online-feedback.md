# 线上答案反馈

在智能网关的 AI 对话页面，每条完整回答下方提供「有帮助 / 不满意」。点踩可选原因与补充意见，不要求用户进入模型测评平台。测评平台的「线上用户反馈」仅管理员可见，汇总满意率、反馈覆盖率以及最近 50 条反馈。原来的星级评分标为「人工评测评分」，用于管理员离线评测。

## 自有业务页面接入

业务后端使用原有网关 API Key 调用 `/api/v1/chat/completions`，然后将网关返回的 `id` 与完整回答一起发给业务前端。非流式结果的 `id` 与 `gateway.traceId` 相同；流式结果的所有事件使用同一个 `id`，收到 `finishReason: stop` 时回答已入库，可以评价。缓存命中也返回新的调用 ID，反馈归属实际生成答案的模型。`[DONE]` 表示流结束。

前端按钮调用你自己的业务后端。业务后端校验该业务用户确实拥有这条回答，再使用生成该回答时的网关 API Key 提交：

```http
POST /api/v1/feedback
Authorization: Bearer YOUR_GATEWAY_API_KEY
Content-Type: application/json

{"requestId":"网关返回的id","vote":-1,"reason":"incomplete","comment":"遗漏了第二个问题"}
```

`vote` 为 `1`（点赞）或 `-1`（点踩）；`reason` 可选 `incorrect`、`incomplete`、`irrelevant`、`other`；`comment` 可选，最长 2000 字。不要将网关 API Key 放入浏览器。网关按调用所属账号和 API Key 验证权限；同一业务 Key 服务多个终端用户时，还需业务后端验证终端用户的答案归属。

一个调用只保留一份当前反馈。相同内容重复提交不会增加反馈数量或更新时间，改评分会替换原记录。测评调用（有 evaluation run ID）、失败调用、空回答以及上线前未留存的旧回答不能通过该接口评价。控制台使用会话鉴权的 `/api/internal/chat/feedback`，字段相同。

## 统计与画像

- 满意率：点赞数 / 已评价回答数。没有反馈时显示「暂无评价」。
- 反馈覆盖率：已评价回答数 / 可评价的成功非空回答数。
- 不将未评价答案计为满意，也不将点赞转换成准确性或完整度。
- 按实际模型和任务类型分组，首次累计 30 条有效反馈后发布满意度画像。之后每累计 30 条不同回答的新增或修改反馈再发布；相同回答重复修改仅占一条待处理反馈。
- 后端每 30 秒检查一次。画像存于独立表，保留版本号和样本量，失败下一轮重试。已发布满意度最多占自适应路由质量分的 20%，其余 80% 来自原有能力画像；准确性门槛仍基于离线评测。
- 网关对话默认使用「评测与反馈路由」。固定模型、成本优先和延迟优先仍遵循所选策略。

## 已有数据库升级

使用网关虚拟环境运行 `python scripts/migrate_online_feedback.py` 后，重启网关和评测后端。该脚本只创建三张新表，不修改已有任务与结果。新部署由 Docker 初始化脚本 `05-online-feedback.sql` 建表。

新功能会留存线上成功回答的最后一条用户问题、完整回答与反馈，用于管理员查看和追溯；离线测试不另存这些内容。统计从功能启用后的新回答开始，历史回答不补造。
